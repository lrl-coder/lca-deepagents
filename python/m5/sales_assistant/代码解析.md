## 一句话概括

这是 LangChain Academy 的一个多 Agent 销售助理示例：主 Agent 负责理解任务和编排流程，把数据库、邮件、报价审核、新闻调研分别交给专职子 Agent，并用人工审批保护写操作。

```text
用户 / LangGraph Studio
          │
          ▼
  Chinook Sales Assistant
  ├─ AGENTS.md：角色、规则、权限
  ├─ skills/：三套业务流程
  ├─ QuickJS：精确计算
  ├─ 文件工具：生成报告和 Newsletter
  │
  ├─ chinook-analyst ── SQLite / Chinook 数据库
  ├─ inbox-manager ──── MCP 邮件服务 ── mail_store.json
  ├─ quote-reviewer ─── 报价复核
  └─ genre-researcher ─ Tavily 新闻搜索（可选）
```

## 主入口

核心入口是 [agent.py](/D:/project/lca-deepagents/python/m5/sales_assistant/agent.py:46)。

`make_graph()` 创建 Deep Agent，并装配：

- 主模型。
- Markdown 转 HTML、饼图、邮件 MCP 工具。
- 四类子 Agent。
- `/skills` 下的业务操作手册。
- `/AGENTS.md` 长期角色记忆。
- QuickJS 代码解释器，用于金额等精确计算。
- 本地虚拟文件系统后端。

这里的 `virtual_mode=True` 会让 Agent 看到 `/skills`、`/outputs`、`/research` 这样的虚拟路径，而实际文件仍位于项目目录中。

部署入口由 [langgraph.json](/D:/project/lca-deepagents/python/m5/sales_assistant/langgraph.json:1) 声明。`langgraph dev` 会调用 `agent.py:make_graph`，在默认的 `2024` 端口提供 LangGraph API 和 Studio。

## 子 Agent 分工

子 Agent 在 [subagents.py](/D:/project/lca-deepagents/python/m5/sales_assistant/subagents.py:97) 中构建。

| 子 Agent | 职责 | 可用能力 |
|---|---|---|
| `chinook-analyst` | 客户、价格、购买历史、业绩指标 | 只读 SQL、读取 Schema、新增客户 |
| `inbox-manager` | 查收邮件、读取正文、保存回复草稿 | MCP 邮件工具 |
| `quote-reviewer` | 检查数量、单价、折扣和总额 | 纯模型复核 |
| `genre-researcher` | 为 Newsletter 调研单个音乐流派 | Tavily 搜索；只允许写 `/research/**` |

`genre-researcher` 只有设置了 `TAVILY_API_KEY` 才会注册。

主 Agent 和报价审核器使用 `strong_model`，其他子 Agent 使用 `model`。当前两者都配置为 `openai:gpt-5.6-luna`，见 [models.py](/D:/project/lca-deepagents/python/models.py:47)。

## 三条主要业务流程

### 1. 处理报价请求

流程定义在 [rfq-quote/SKILL.md](/D:/project/lca-deepagents/python/m5/sales_assistant/skills/rfq-quote/SKILL.md:10)：

1. `inbox-manager` 读取 RFQ 邮件。
2. `chinook-analyst` 查询客户；新客户需要人工批准后才能写入。
3. 查询真实曲目价格。
4. 用 QuickJS 计算行金额、折扣和总额。
5. `quote-reviewer` 复核。
6. `inbox-manager` 保存回复草稿，再次等待人工审批。
7. 把报价记录追加到 `/outputs/quotes_ledger.md`。

项目自带了一封 Morgan Vale 的批量 Rock/Metal 报价邮件，位于 [incoming_rfq.json](/D:/project/lca-deepagents/python/m5/sales_assistant/mcp/seeds/incoming_rfq.json:1)。

### 2. 生成销售区域报告

定义在 [territory-report/SKILL.md](/D:/project/lca-deepagents/python/m5/sales_assistant/skills/territory-report/SKILL.md:11)：

- 查询 Jane 名下客户的总收入、订单数、头部客户和流派收入。
- 生成 Markdown 报告。
- 使用 `render_pie_chart` 生成收入饼图。
- 写入 `/outputs/territory_report-<date>.md` 和 `territory_chart.png`。

### 3. 生成每周 Newsletter

定义在 [weekly-newsletter/SKILL.md](/D:/project/lca-deepagents/python/m5/sales_assistant/skills/weekly-newsletter/SKILL.md:10)：

- 从数据库选出热门流派。
- 每个流派启动一个 `genre-researcher`，并行调研。
- 主 Agent 汇总 Markdown。
- 转换成经过 HTML 清洗的页面。
- 保存到 `/outputs/newsletter-<timestamp>.html`。

HTML 使用 `nh3.clean()` 清除搜索结果中可能混入的脚本，见 [html.py](/D:/project/lca-deepagents/python/m5/sales_assistant/tools/html.py:39)。

## 数据和邮件如何处理

数据库工具在 [sql.py](/D:/project/lca-deepagents/python/m5/sales_assistant/tools/sql.py:50)：

- 查询连接使用 SQLite `mode=ro`。
- 只接受单条 `SELECT` 或 `WITH`。
- 额外拦截 `INSERT`、`UPDATE`、`DROP`、`PRAGMA` 等关键词。
- 唯一写入口是 `add_customer()`。
- 新客户强制归属 Jane Peacock，即 `SupportRepId = 3`。
- 插入使用参数化 SQL，并检查重复邮箱。

邮件不是实际 Gmail，而是本地模拟 MCP 服务：[mock_mail_server.py](/D:/project/lca-deepagents/python/m5/sales_assistant/mcp/mock_mail_server.py:22)。它提供：

- `mail_list_messages`
- `mail_read_message`
- `mail_create_draft`

邮件状态最终保存在运行时生成的 `mcp/mail_store.json` 中。

## 人工审批机制

两个动作会暂停 LangGraph 执行，等待 `approve`、`edit` 或 `reject`：

- `add_customer`
- `mail_create_draft`

配置分别位于 [subagents.py](/D:/project/lca-deepagents/python/m5/sales_assistant/subagents.py:124) 和 [subagents.py](/D:/project/lca-deepagents/python/m5/sales_assistant/subagents.py:147)。

这不是“Agent 在对话里询问一句是否同意”，而是真正的图执行中断；客户端批准后再通过 `resume` 恢复运行。
