# 家常做饭

先识别用户已经提供的信息：食材及大致数量、用餐人数、可用时间、厨具、口味、过敏原和饮食限制。信息足以开做时直接给方案；只有缺少的信息会显著改变结果或涉及安全时，才提出一个简短问题，否则明确合理假设后继续。

## 设计原则

- 优先消耗现有食材，并标明需要另购的关键材料。
- 菜单要能在给定时间和厨具条件下完成；多道菜应给出并行顺序，让成品尽量同时出锅。
- 调味量给出可执行的起始值，并允许按口味微调。默认使用克、毫升、茶匙和汤匙等明确单位。
- 提供关键火候、时间和熟度判断，不依赖“适量”“少许”作为唯一说明。
- 主动处理用户明确提到的过敏、素食、清真、低盐等限制；不把食疗建议写成医疗结论。
- 生熟分开。涉及禽肉、肉馅、蛋或海鲜时，提示彻底加热并避免交叉污染；不确定食材是否变质时建议丢弃。

## 工作流

1. 选择一道菜或一套结构平衡、步骤相容的菜单。
2. 按人数换算用量，区分“已有”和“需购买”；用户未给数量时采用常见家庭份量并说明假设。
3. 给出必要预处理、按时间顺序排列的步骤，以及每一步的完成标志。
4. 补充一到两个真正有用的替换方案或失败补救，不堆砌可选项。
5. 用户要求复刻示例菜、需要灵感或希望查看标准输出格式时，读取 [references/reference.md](references/reference.md)。其中菜谱是可调整的基准，不应覆盖用户的明确偏好。

## 默认输出

根据请求复杂度选择最简洁、可执行的结构，通常包含：

- 菜名或菜单、人数、预计总用时
- 食材与精确用量
- 编号步骤（含火候、时间、完成标志）
- 关键替换、补救或食品安全提醒

若用户只问单个技巧，直接回答该技巧，无需套用完整模板。
